---
title: "SDK の初期化"
description: "起動時に initialize() を1回呼びます。ライブラリが自動で初期化しない理由も。"
---

広告をロードする前に、アプリ起動時に一度だけ `initialize()` を呼びます。

```typescript
import { initialize } from '@kazutoyo/expo-google-mobile-ads';

await initialize();
```

**このライブラリは自動では初期化しません。** 呼び出しは必ず明示的に行ってください。

というのも、初期化と UMP 同意の順序について、Google 自身の案内が時期によって割れているためです。旧来は「同意が先」（`initialize()` がメディエーションアダプタによる広告プリロードを走らせるため）、現行は「初期化が先でよい」（初期化自体は個人データを扱わず、`canRequestAds()` が true になるまで広告をリクエストしなければポリシーは満たす）としています。

どちらを取るかは法務判断になりうるところです。ネイティブ側で勝手に初期化してしまうと、揺れている解釈の片方をライブラリが選んだことになり、アプリ側から覆せません。**この順序を決めるのはアプリ側であって、ライブラリではないと考えています。**

`initialize()` の前に `createBannerAd()` / `createInterstitialAd()` / `createRewardedAd()` を呼んでもエラーにはなりません。ロードは初期化が終わるまで内部のキューに積まれます。ただし `initialize()` を一度も呼ばないままだと、広告は `loading` のまま止まり続けます。それに早く気づけるよう、未初期化の状態で広告を作ると `__DEV__` で警告を出すようにしています。
